# Flowglass 优化、简化与美化计划

> 状态：已进入实施；阶段 1–4 与 A–D 的最小能力已落到源码，阶段 5 完成必要组装收敛，阶段 0 / 6 的真实宿主与发布验收仍有待办。
> 实施记录：[flowglass-ux-implementation.md](flowglass-ux-implementation.md)；测试与量测：[flowglass-ux-baseline.md](flowglass-ux-baseline.md)。
> 下面保留最初调研、目标和验收门槛。勾选表示源码及相应离线检查已完成，不代表所有真实部署环境已验收；未安装或发布。
> 调研日期：2026-09-20。
> 目标：让用户更快看懂执行进度、定位问题、比较分支，同时让 Flowglass 更自然地融入 DeepSeek Harness。

## 1. 推荐方向

Flowglass 应收敛为 **Harness 内的执行观察与分支比较面板**。日常打开时，先回答三个问题：当前在做什么、哪里需要关注、下一步可以做什么。需要追查时，再展开工具输入输出、系统上下文、完整拓扑与原始事件。

建议按这个顺序推进：

1. **先简化信息层级**：统一“流镜 / 大流镜 / 全景 / 近观”的导航关系，区分观察对象、展示方式与内容密度。
2. **先解决窄侧栏可用性**：根据 Flowglass 容器宽度调整布局，让普通查看无需横向拖动或反复缩小。
3. **再统一视觉语言**：沿用 Harness 主题、基础组件和侧栏行为，用少量颜色表示状态，减少网格、徽章、描边和透明材质的叠加。
4. **再切开交互与刷新**：优先让发送区和详情区脱离整块 HTML 更新，解决“保住草稿就暂停实时刷新”的现有取舍。
5. **最后按实测优化模型与渲染**：保留现有事件驱动刷新、缓存和历史分页，对确有成本的部分做增量更新。

首个可交付版本应完成导航、窄栏布局、卡片层级、详情、状态与键盘操作，不以重写全部渲染器为前提。用户已授权自主规划功能增强；在此基础上，推荐增加查找、异常聚合、关键节点标记与分支结论对比，将 Flowglass 从被动展示流程推进到可定位、可追查、可比较的工作面板。

## 3. 与 DeepSeek Harness 的协同原则

### 3.1 宿主负责承载，Flowglass 负责内容

保留“原生右侧栏 → Better Sidebar 桥 → 固定面板”的现有单路径承载顺序。支持原生能力时，标签页、分栏、关闭、面板尺寸与全屏交给 Harness；Flowglass 内容区不重复绘制另一套窗口控制。

Harness 的普通停靠与全屏应复用同一内容树。切换时保留选择节点、详情、草稿、滚动位置与拓扑视口；不以重新打开整个 Flowglass 来实现放大。

侧栏的“流镜”入口继续存在，但注册与导航应优先走宿主公开扩展点。现有 DOM 注入路径仅作为明确版本下的兼容实现，在确认等价能力后逐步收敛，不能先删后补。

### 3.2 复用宿主视觉和交互

- 颜色优先映射 Harness 的 `--dsw-*` 语义变量；Flowglass 只增加节点角色、连接线、画布等领域 token。
- 字体继承宿主，正文继续使用官方 Markdown 渲染与代码显示行为。
- 菜单、按钮、提示、开关、输入与弹层优先复用可公开消费的 UI primitives。HTML renderer 暂未迁移时，先复用 token 和语义行为，避免为复用一个按钮就强制改造整张画布。
- 完整设置继续放在官方插件详情的 `plugins.bundle.config` 扩展点；面板“更多”只提供快捷选项与设置入口。
- UI 文案统一为中文产品术语，保留 locale 接入位置；未来若修改 Harness 自身，遵守其 typed dictionaries 与 `t` 的要求。
- 订阅、注册、样式与副作用按宿主生命周期释放。不要为视觉改造修改 agent loop、Session 日志格式或既有持久化历史。

## 4. 信息架构与术语

### 4.1 产品与导航收敛

产品统一称为 **Flowglass · 流镜**。主界面只保留两个观察范围：

- **当前会话**：观察一条会话的执行过程，允许进入子代理和查看节点详情。
- **并发任务**：观察一组分支的进度、差异与历史关系。

“大流镜”可在迁移说明中保留为旧称，逐步从常驻按钮和标题移出。“全景/近观”改为明确的上下文导航：并发任务 → 分支 A → 子代理 B，提供可点击面包屑返回。

| 现有概念 | 建议显示 | 说明 |
| --- | --- | --- |
| 实时流镜 | 当前会话 | 说清观察对象 |
| 大流镜 / 全景 | 并发任务 | 产品内的一个工作范围 |
| 近观 | 当前分支 + 面包屑 | 保留来自哪组任务的信息 |
| 精简 | 概览 | 默认显示分支摘要与最新结果 |
| 详细 | 对比 | 按轮次比较，可展开每个分支的完整过程 |
| 导图 | 关系图 | 显示派生、沿用和历史轮次 |
| 注入 | 系统上下文 | 默认折叠，详情可区分原始事件类别 |
| 子代理跟随 | 查看时同步切换主会话 | 准确说明操作副作用 |
| ⇪ | 带入其他会话 | 用文字或有名称的图标操作代替陌生符号 |

“当前会话”与“并发任务”是观察范围；“概览 / 对比 / 关系图”是并发任务的展示方式；“显示系统上下文 / 显示技术信息”是内容过滤。三个维度分开，不再平铺成多组含义重叠的按钮。

### 4.2 默认行为与迁移

1. 新用户首次打开且无并发上下文：进入当前会话。
2. 明确从并发任务或分支入口进入：恢复对应任务上下文。
3. 老用户已有保存的视图：按语义迁移，不强制重置成新默认。
4. 旧 `compact/detail/map` 分别映射为概览/对比/关系图；初期可保留内部枚举，仅更改呈现。
5. “查看分支”与“同步切换主会话”保持可区分。首版保留已有跟随偏好；关闭跟随时，提供显式“在主会话打开”。
6. 关闭面板后不因后台刷新自行弹回；切换 Session 时是否保持展开继续遵循现有设置。

### 4.3 操作层级

| 层级 | 常驻内容 | 按需内容 |
| --- | --- | --- |
| 顶部上下文栏 | 范围/面包屑、会话或任务标题、运行/异常摘要 | 标识符、完整模型路由、技术统计 |
| 工具栏 | 当前范围所需的视图选择、筛选入口、更多 | 手动刷新、同步选项、跟随说明、帮助、设置 |
| 当前会话底部 | 有新内容时的“回到最新” | 缩放和画布操作只在需要时出现 |
| 并发任务操作 | 一个明确的“继续任务”或“创建并发任务”入口 | 展开的发送区、模型、目标分支数与复用选择 |
| 节点 | 摘要、状态、选中反馈 | 详情、分支、复制、带入其他会话 |

正常同步状态用安静的状态提示；暂停、同步错误、过期数据必须保持可见。手动刷新可放入菜单，出错时直接显示“重试”。不要为了减少按钮数隐藏异常恢复入口。

## 5. 布局方案

### 5.1 当前会话的建议结构

```text
流镜  /  当前会话                 运行中 · 1 个工具   ⋯
任务标题                         筛选
─────────────────────────────────────────────────────
用户      任务摘要
          └ 系统上下文 · 2 项          [展开]
助手      当前步骤 / 回答摘要
          ├ 工具名称   正在运行 · 已等待 8 秒
          └ 工具名称   已完成 · 输出摘要
子代理    子任务名称   运行中 · 3 步     [查看]
助手      最近结论
─────────────────────────────────────────────────────
                                  有 3 条新内容 ↓
```

这是一份结构示意，不代表将所有视图强制改成列表。宽面板继续保留 Flowglass 的泳道与连接线辨识度，窄面板使用可读性更好的纵向结构。

### 5.2 按容器宽度自适应

使用容器查询，或在需要布局计算时使用稳定的容器尺寸观察。判断依据是 **Flowglass 可用内容宽度**，不是整个浏览器宽度；宿主侧栏收放、分栏与 Inspector 打开都会改变可用空间。

| 可用宽度，建议起点 | 当前会话 | 并发任务 | 详情 |
| --- | --- | --- | --- |
| 小于 480px | 单列时间流；工具/子代理作为节点组内条目 | 纵向分支摘要；选中分支后进入过程 | 替换内容区，保留返回与标题 |
| 480–799px | 主线 + 可折叠的执行条目，避免硬撑三泳道 | 概览优先；对比采用分支选择，不强塞多列 | 独立覆盖层或内容替换，返回恢复位置 |
| 800–1199px | 主线与执行泳道；按内容决定是否启用第三列 | 可以比较两条分支，其余通过选择器切换 | 只有剩余主区仍可阅读时才并排 |
| 1200px 及以上 | 完整泳道；适当限制正文宽度 | 2–4 列比较与完整关系图 | 可并排 Inspector，建议宽 320–400px |

这些断点需要用实际中文标题、工具输出和宿主字号校准。普通时间流不应出现水平滚动；关系图与用户明确选中的多列对比允许平移/横向滚动，并提供“适应画布”。

### 5.3 详情 Inspector

- 顶部固定显示“节点类型 + 标题 + 状态”，保留关闭/返回和一个主要动作。
- 消息详情默认渲染正文；元数据放在可展开的“技术信息”。
- 工具详情先给出工具名称、完成/失败状态与结果摘要，然后显示“输出 / 输入 / 原始数据”。
- 失败详情直接展示可理解的失败原因；原始错误仍可查，不用一大片 JSON 作为第一屏。
- 长代码、JSON 和原始输出独立滚动，避免把整个面板撑宽。
- 窄栏用内容替换；宽栏用并排。模态模式需要焦点约束，并排模式不锁住整个面板焦点。
- `Escape` 关闭最上层，焦点回到触发节点；继续实时刷新时不重置阅读位置和已选文字。

### 5.4 并发任务概览与比较

**概览**以分支摘要为主：分支名、运行状态、当前步骤、最新结论、需要关注的错误。相同模型可在任务层显示一次，分支采用不同模型时再单独标注。

**对比**按明确的轮次与来源对齐：共享输入先显示一次，分支结果分别呈现。没有同源轮次证据时标注“未对齐”，不能仅按数组序号断言两个步骤相同。

建议增加“仅看差异”过滤，但保留“显示全部”。差异分为输入、执行步骤、文件、结果等已能可靠推导的维度；“不同”不等于“错误”，使用中性色或轻量强调，不统一标红。缺少文件级证据时不生成虚假的文件 diff。

**关系图**保留历史轮次、沿用与派生关系。首次进入根据内容边界居中并适应视口；之后保留用户缩放和平移，不在每次刷新时重新排版。提供“适应画布 / 定位选中 / 恢复布局”，缩放范围应覆盖 4 分支，不能只沿用当前最低缩放档位就声称支持完整适配。

不在首版引入自由编辑图、自动编排新工作流或另建任务看板。

## 6. 内容简化规则

### 6.1 节点卡片

| 节点 | 默认展示 | 展开后展示 |
| --- | --- | --- |
| 用户消息 | 角色、2–3 行任务摘要 | 完整正文与时间 |
| 助手消息 | 回答摘要或当前状态；失败/中断明确显示 | 正文、模型、用量、耗时、分支操作 |
| 工具调用 | 规则化名称、状态、主要参数/结果一行摘要 | 完整输入、输出、错误和原始工具名 |
| 子代理 | 子任务名称、状态、当前步骤、返回入口 | 完整子流程与委派参数 |
| 系统上下文 | “系统上下文 · N 项”折叠条 | 按原顺序查看每条内容与类型 |
| 重试/取消 | 明确的终态与可追查的尝试次数 | 该次尝试的细节与最终结算 |

系统上下文折叠仅改变展示，不删除原始数据、不改变事件顺序、不把隐藏内容默认为已选中或已带入草稿。若用户在节点组上进行批量选择，应明确实际包含哪些事件。

时间和模型不必在每张连续卡片上重复。角色变化、模型变化、跨轮次和错误节点仍显示必要的上下文；完整数据始终能从详情获取。

### 6.2 工具组

- 连续且属于同一执行步骤的已完成工具，可折叠为“已完成 5 个工具”。
- 运行中、失败、需要关注的工具默认展开。
- 并行调用保留并行语义，不通过折叠把它们画成串行执行。
- 工具摘要继续复用现有声明式规则；不为美化另建一套命令识别逻辑。
- 首版先实现显示分组，不同时改写工具解析与调度语义。

### 6.3 状态文案

区分两个独立维度：**执行状态**与**数据同步状态**。执行已结束但面板仍在同步检查时，不显示为“任务运行中”；页面暂停同步时，不把任务标成暂停执行。

| 执行状态 | 建议文案 | 表达 |
| --- | --- | --- |
| 尚无事件 | 等待第一条消息 | 空态引导 |
| 助手流式生成 | 正在生成 | 轻量动效，可降低动效 |
| 工具未返回 | 工具运行中 / 已等待 N 秒 | 状态图标与文字 |
| 正常结束 | 已完成 | 次要颜色，无持续动画 |
| 失败 | 执行失败 | 错误摘要和查看详情 |
| 被中断/取消 | 已中断 / 已取消 | 保留已产生内容 |
| 状态不足以判断 | 状态未知 | 不伪装成成功 |

同步状态采用“已同步 / 更新中 / 已暂停同步 / 同步失败”，错误时提供重试。需要时显示最后成功更新时间。

## 7. 视觉规范

视觉方向：**深浅主题一致、正文清楚、控件安静、状态突出**。保留流镜的图形特征，让内容与结构承担主要辨识度。

### 7.1 Token 与样式范围

| 层次 | 推荐处理 |
| --- | --- |
| 面板背景 | 跟随宿主 base/layer token，不再叠加大面积渐变 |
| 节点背景 | 单一实色或接近不透明的 surface；选中时改变边框/背景之一 |
| 文字 | primary / secondary / tertiary 三层；正文使用 primary |
| 角色 | 图标、短标签与轻量侧边标记；不把整张卡涂成角色色 |
| 状态 | 运行、成功、警告、失败各自语义色，同时有文字或图标 |
| 边框 | 常态低对比；选中和键盘焦点明确可见 |
| 连接线 | 比正文更弱；活动路径可短时强调 |
| 画布 | 普通时间流去掉网格；关系图可使用更弱的网格 |
| 玻璃材质 | 现有材质保留在少量浮层；正文和详情提高不透明度 |

Flowglass 新样式约束在自己的根作用域内；共享 `.tb-*` 的改动必须检查动态 Toolbox 与其他静态 bundle。领域变量建议为 `--fg-*`，作为现有 `--tb-*` 与宿主 token 的适配层，不平行维护两套主题值。

### 7.2 尺寸建议

- 间距基准：4 / 8 / 12 / 16 / 24px。
- 常规正文：13–14px；详情正文建议 14px 起；元数据一般不低于 11–12px，并尊重用户字号倍率。
- 正文行高：1.5–1.65；卡片标题使用中等字重，避免整卡粗体。
- 公开 Button 优先采用宿主常规 36px / 紧凑 28px 的规格与外形；画布专用图标控件可采用 30–32px，保持合适点击范围。
- 节点圆角：8px 左右；浮层 10–12px；不让所有元素都变成胶囊。
- 长标题最多两行；ID、模型路由等技术内容使用截断 + 可访问完整值，正文摘要按行数截断。
- 普通交互优先使用宿主现有 0.1s / 0.2s / 0.3s 动效变量与 easing；完成态停止流光和脉冲。

数值是初稿，应优先遵循宿主当前 primitives 的规格，再通过截图确认。不要同时引入新字体、图标库、大面积插画或另一套 UI 框架。

## 8. 交互细节

### 8.1 实时更新与阅读

- 用户位于底部且正在跟随最新时，新内容自然进入视口。
- 用户向上阅读、框选或打开详情时，不强行拉回底部；显示新内容数量。
- 补历史前记录节点锚点，补入后恢复相对位置；加载失败在当前位置提供重试。
- 显式用户动作优先于后台响应；旧 Session、旧视图、旧详情请求的迟到响应不能覆盖当前选择。
- 后台不可见时暂停 Flowglass 主动刷新，允许已经发出的请求收尾；重新可见后合并更新。
- 正在编辑发送草稿时，草稿、选择范围和焦点保持稳定，同时继续展示执行进度。

### 8.2 发送与分支

保留能力，收敛入口。进入发送区后必须清楚呈现：来源会话/回答节点、目标分支、目标数量、是否新建会话、是否沿用当前会话。

- 当前会话发起 1→N：按钮写“创建 N 个分支并发送”或“沿用当前 + 新建 N−1 个分支”。
- 并发任务继续 N→N：按钮写“发送到 N 个分支”，不能只写“开始”。
- 从历史节点派生：发送区显示“从第 X 轮派生”，并说明原历史会保留。
- 部分分支发送失败：逐项显示结果，仅对明确失败项提供重试；发送回执丢失等“结果未知”情形先核对状态，不直接再次发送。已成功项不得随整组重试重复发送。
- 带入其他会话：默认保留现有草稿路径；直接发送继续保留为明确选择，不能把预览点击变成发送。
- 高级模型/思考强度设置可收起，但已选值与各分支差异要能看见。

### 8.3 键盘与辅助技术

- 消息、工具、分支卡均能通过键盘打开；含多个操作的卡片避免嵌套按钮，使用独立“查看详情”焦点目标。
- 菜单与分段切换采用对应语义；图标按钮提供名称，选中/展开状态可被读出。
- 不把未知快捷键加入全局；面板内快捷操作必须确认与 Harness 冲突情况。
- 拖动、框选、平移均有按钮或普通选择的替代路径。
- 使用 `prefers-reduced-motion` 停止持续动画，保留状态文字。
- 动态状态以摘要播报，避免每个 token 都触发朗读；参考 [W3C 状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。
- 正文对比度目标至少 4.5:1，大字号文字至少 3:1，按实际前景/背景组合测量；参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 常规点击目标优先做到至少 24×24 CSS px，并优先采用更舒适的 30–32px 桌面控件；24px 标准存在间距等例外，不能单靠尺寸声称整个产品合规。参考 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 9. 设置页简化

完整设置继续使用当前官方插件详情入口，分为“行为”“显示”“工具规则”。默认分支数、默认视图与刷新设置仍保留。

工具规则默认显示紧凑列表：启用开关、规则名称、匹配摘要、显示预览和编辑入口。点“编辑”后展开当前规则字段，不让六条内置规则同时占满页面。

保留规则的顺序语义：第一条命中生效。若增加重排，必须同时提供键盘上下移；保存前给出匹配示例，不执行示例命令。

新增设置应有明确理由。优先增加“系统上下文默认折叠”和必要的内容密度选项；色彩、间距、布局断点不全部变成面向用户的选项。

保存/放弃仍体现脏状态；恢复内置规则清楚说明影响范围。迁移既有自定义规则，不能通过清空 localStorage 达成新样式或新默认。

## 10. 推荐新增功能

新增功能按“减少查找时间、提高异常可见性、支持结果复用”的收益排序，嵌入现有面板，不为每个功能新建一级导航。以下是主动选择的产品路线，不是要求一次性把所有功能都做完。

### 10.1 节点搜索与组合筛选，P1，优先实现

**解决的问题**：长会话里仅靠滚动找命令、错误或某个回答，成本高；默认折叠系统信息后，也需要可靠的找回入口。

**交互方案**：工具栏一个搜索入口，展开后输入关键词；结果支持按消息/工具/子代理、运行/失败/完成、当前分支等条件筛选。展示命中数、前后跳转与“清除筛选”。点击结果定位并临时展开对应分组。

**数据范围**：第一步明确标注“搜索已加载内容”；全会话搜索只能在已有查询服务或补齐 Host 查询/索引后提供。界面不能在仅加载 60 个节点时显示“全会话无结果”。输入输出的完整搜索与卡片摘要搜索也应区分。

**宿主复用**：Harness 已有 [sessionQuery.searchEvents/filterEvents](D:/github/dsh/deepseek-harness/packages/session-query/session-query/src/index.ts:164)。先检查部署的查询服务与 SQLite 搜索后端，优先复用后再补 Remote 暴露。Client 的 `sessions.search()` 是有数量限制的可见消息索引，不能等同于工具输入输出的全历史搜索。Host 查询本身不负责调用者授权，Remote 必须绑定当前来源与允许访问的 Session，不能接受任意来源后直接转发查询。

语义搜索的内容范围以宿主 [extraction.ts](D:/github/dsh/deepseek-harness/packages/session-query/session-query/src/extraction.ts:15) 为准；reasoning、原始 stream、request envelope 和未知扩展事件不在其默认语义提取范围。界面说明应准确，不能声称所有原始字节都可检索。

**实现**：摘要结果包含 Session、稳定节点身份、匹配片段与分页定位信息；打开未加载节点时先加载目标窗口，再滚动定位。取消/切 Session 后丢弃旧结果，沿用当前源和工作区边界。

**验收**：组合 A 验证已加载窗口内的关键词、状态筛选与定位，并始终准确说明搜索范围；组合 B 再验证从超过 1000 条事件样本中找到未加载的更早失败工具并打开详情。两者均不能改变真实节点数量统计或永久隐藏已选内容。

### 10.2 “需要关注”摘要，P1，与首版状态整理一并设计

**解决的问题**：错误、长时间未返回的工具、分支失败、同步失败散落在画布各处。

**交互方案**：仅在有需要关注的事项时，在标题下显示一条紧凑摘要，例如“2 个执行失败 · 1 个工具仍在等待”。点摘要展开列表，点条目定位到节点；正常时不占用固定大卡片。

**数据来源**：使用真实工具/attempt 终态与同步结果。只有“等待时间较长”的事实时，显示已等待时长，不自动判定为死锁、超时或错误。阈值如需要可配置，默认值先依据 fixture 和现有行为确定。

**约束**：面板只解释已有事实；不默认发起模型诊断、运行命令、重试业务工具或中断任务。执行失败与 Flowglass 同步失败分组展示。

**验收**：流式失败结算后同一问题不会出现两次；切到其他会话不会带入旧错误；已解决事项更新状态并保留原始节点可查。

### 10.3 关键节点标记与定位，P1

**解决的问题**：重要结论、失败原因或值得保留的工具结果在长流程中难以再次找到。

**交互方案**：节点更多菜单提供“标记节点”，允许一行简短备注；工具栏菜单中打开标记列表。首版在本浏览器定位，后续才评估跨设备同步或外部深链。

**数据设计**：保存宿主来源、工作区/Session、节点稳定身份、简短备注与创建时间；不复制完整会话正文。节点已归档、不可访问或在历史迁移后无法定位时显示失效原因，不跳到错误节点。

**宿主协同**：面板内导航可使用右栏 navigation params。只有真实可用的路由与授权范围已明确后，才提供“复制节点链接”；不自行发明无法打开的 URL scheme。

**验收**：刷新和切会话后能恢复标记；备注不污染 Session；删除标记只删除标记，不删除消息或工具结果。

### 10.4 分支结论对比与带入草稿，P1，主要增强

**解决的问题**：现有分支图能看到执行过程，但用户仍需逐个进入分支才能读完结论并决定下一步。

**交互方案**：在并发概览中展示各分支最新已完成回答的摘要；支持选择两至四条结论进入对比。选择内容后“带入会话草稿”，草稿按分支标明来源、轮次和节点。

**数据语义**：比较已完成回答与运行中草稿必须明确区分；没有同源轮次时仍可并排阅读，但不能声称是同条件比较。已有 ⇪ 带入能力继续复用，新功能主要补齐来源、选择范围和汇总展示。

**默认处理**：首版只做确定性摘录和用户选取，不自动调用模型评判哪个答案正确。未来如加入 AI 总结，需要单独选择、明确调用模型和目标会话，不能让打开对比视图就产生请求或费用。

**验收**：带入的文本与所选节点相符，包含来源；取消不改变目标草稿；部分分支无结论时显示“尚无完成回答”；不会自动发送。

### 10.5 历史执行回放，P2，数据语义验证后实施

**解决的问题**：静态历史图难以解释分支何时发生、某个错误前经历了哪些步骤。

**交互方案**：从已完成轮次进入只读回放，按事件/步骤前进、后退，支持跳到工具失败或分支节点。常态实时界面不持续展示播放器。

**边界**：回放只改变可视事件范围，不重新执行命令、调用模型或改写日志。优先按真实事件顺序回放；只有持久流式数据与时间戳充分时才提供按时间播放。缺失的数据标为不可重建，不能伪造当时状态。

**实现依赖**：复用宿主已提交 Session 事件，单独定义 replay cursor，与 live revision 分离。每个回放位置从此前的 durable event 前缀重新折叠，或读取等价 checkpoint；不能仅把最新 projection 的后续节点隐藏，因为工具结果和最终状态可能已写入较早卡片。当前 projection/turnOutline 不自动等于历史状态快照。退出回放恢复原来的实时位置和视图。

**验收**：同一 fixture 回放结果确定；不会新增任何业务请求；包含失败/重试/取消；进入与退出回放不覆盖 live 状态。回退到工具已开始、结果尚未产生的位置时，不能出现未来结果、最终状态或尚未出生的分支。

### 10.6 快照与脱敏诊断导出，P2

**解决的问题**：沟通执行结果、复现 Flowglass 展示问题时，缺少小而明确的可分享材料。

**交互方案**：更多菜单提供本地导出，明确选择“当前图快照”或“诊断摘要”。图快照包含当前视图与图例；诊断摘要只包含版本、视图设置、节点/状态计数、错误类型与用户选择的内容。

**默认范围**：不自动包含完整系统提示词、原始命令输入输出、认证 URL、绝对路径或隐藏节点正文。用户选择包含明细时先预览；导出只写本地文件，不自动上传。

**实现依赖**：先确定 SVG/PNG 与 JSON/Markdown 的最低可用格式；本地图片、跨源资源和字体影响图导出时给出可理解的降级提示。诊断结构有版本号，避免把完整持久化日志当作诊断文件。

**验收**：默认导出无隐含正文和认证参数；文件可打开；内容范围与预览一致；失败不影响正在查看的流程。

### 11.2 第一阶段保持现有协议

先通过 HTML 输出结构、CSS、语义属性与动作映射完成信息层级和自适应改造，保留 `{html, state}` 路径、事件解析、分支发送与历史模型。

新增字段需经现有 state/preferences 归一化；数据与展示语义分开。不要把“默认隐藏系统上下文”变成在 `parseItems` 中删掉这些事件。

### 11.3 优先拆出 Composer，再拆 Inspector

1. 将发送区迁为稳定 React 组件，放在会被替换的 HTML 容器之外。
2. 草稿按宿主来源、工作区、任务/历史与来源会话区分；持久化范围要明确，不能把一个分支草稿恢复到另一个分支。
3. 显式传递发送上下文，不再依赖从当前 DOM 临时猜测目标。
4. 使用现有发送/分支 API；点击后保持进行中反馈和逐分支结果。
5. 完成浏览器验证后，再移除“输入非空暂停刷新”的保护，不能先删保护再补稳定组件。
6. Inspector 使用稳定节点身份和独立内容状态；画布变化不重挂载用户正在阅读的详情。

逐分支恢复还需要补 Client 操作状态：保存目标 Session、create/configure/send 阶段、请求结果与可核对的标识，区分明确失败和结果未知。当前 `executeZoomLaunch` 主要返回成功 Session 数组与错误字符串，不能独自保证安全重试。创建成功但配置失败时复用该 Session；发送结果未知时先用可用服务核对，无法判定则保留未知状态并由用户选择后续操作，不声称实现了服务端不具备的 exactly-once 发送。

结构化数据可以通过新增可选字段或独立 Remote 方法提供，但必须先验证 wire 类型、静态 Host/Client/Remote 生成与旧消费者处理。普通 Toolbox 工具的 `{html,state}` 面板协议继续作为受支持的通用能力，不因 Flowglass 迁移而废弃；Flowglass 自身的两种渲染路径共用业务模型，避免业务逻辑分叉。

### 11.4 后续渲染模型

建议分清三类状态：

- **执行事实**：原始事件、attempt、工具结果、会话关系，来自 Host/宿主服务。
- **派生展示数据**：节点摘要、状态、分组、拓扑布局，尽量纯函数计算。
- **本地交互状态**：筛选、折叠、选中、草稿、详情、缩放/平移，归 Client。

节点身份不能只用数组下标。沿用现有 attempt/首事件 seq 的结算连续性，再结合 Session 标识和节点类型形成稳定 key；流式草稿结算时不能重复卡片，也不能让详情或框选脱落。

缓存键应覆盖实际影响结果的 Session、durable/live revision、规则版本，以及分页窗口和相关显示选项。不要只按 Session 缓存导致实时状态或规则更新不生效。

只有测量证明 HTML 重绘仍构成主要成本时，才逐步将画布迁为 keyed React 节点。默认不引入大型图编辑框架；只有关系布局和交互需求已超出当前实现且能删掉足够维护代码时，再单独评估依赖。

### 11.5 文件拆分约束

建议形成样式、偏好/规则、Host 投影、Host 展示、Client 宿主适配、刷新调度、交互、设置等职责组。具体目录名在阶段 0 定稿。

当前动态加载存在源码拼接和 `new Function` 求值，静态构建也读取实现文件。不能直接向现有脚本加入 ESM imports 就假定两条构建链都能运行；先统一 source assembly，再逐步抽取模块，每次保持动态与静态生成可验证。

旧规则面板 `presentationRulesRail` 与旧 action handlers 可列为清理候选，但必须先检查动态 Toolbox、历史 state 和外部动作调用面。官方设置已经接管配置，不代表旧处理函数可以无条件立刻删除。

### 11.6 Toolbox 兼容性是发布门槛

**实施要求：Flowglass 改造后，Toolbox 继续正常使用。** 这是需要验证的兼容承诺，不是仅凭本计划就能判定已实现的结果。两者共享 `plugins/toolbox/client.js`、部分样式、runtime 与构建组装；必须按下面三种形态分别验收。

| 运行形态 | 改动如何到达运行环境 | 必须保留 |
| --- | --- | --- |
| 独立 `dsh-flowglass` 静态包 | 重新构建并安装该包 | 新界面、原生侧栏、静态 Remote |
| `dsh-dynamic-toolbox` 发布包 | 虽名为 dynamic，当前是原生静态合集；重新构建/升级时包含共享源码变化 | 全部工具入口、独立组件启停、普通 HTML 面板、现有数据 |
| 源码动态 Toolbox | Client 通过 RPC 读取磁盘源码，插件重跑/重载时加载变化 | 动态 loader、注册表、重建/启停、timer 清理与原有批准流程 |

单独安装独立 Flowglass 包通常不会替换另一个已安装 Toolbox 包的文件，但两者在同一页面运行时仍需检查共享样式与宿主注册冲突。不能把“安装目录不同”当作无需回归的依据。

具体约束：

1. **通用框架保持稳定**：工具注册、分类导航、`panel` RPC、`{html,state}` 响应、`data-action/data-field` 事件委托及工具业务存储不随 Flowglass 改造而删除或改变语义。
2. **增强只作用于目标面板**：Flow 专用样式限定到 `[data-flow]` 等明确根节点，稳定 React 渲染只接管 Flow 面板；其他工具继续使用通用面板路径。发布形态特有依赖采用显式能力检测/构建声明，不能让 Toolbox 因缺少 Flowglass 专用注入而启动失败。
3. **保护共享样式使用者**：`flowedit` 实际复用了 `.fl-row/.fl-node/.fl-branch-*`。不能全局重定义或删除这些类后只验收 Flowglass；可保留基础样式并对 `[data-flow]` 做局部覆盖，或先让使用者迁移到独立样式。
4. **维持命名空间与数据归属**：沿用 `RT.rpc/storageKey/event/slot` 等前缀隔离，不清空 Toolbox 设置、规则或工作区业务数据；独立 Flowglass 与 Toolbox 同时启用时不能串状态或互相卸载入口。
5. **新增功能按能力启用**：Toolbox 内嵌的 flow 至少保留既有查看/钻取/详情/分支功能；查询、回放等新能力缺少依赖时给出明确不可用原因，不能阻断其他工具。新功能是否在三个形态同时上线，应在该版本的能力矩阵中说明。
6. **三条产物/加载路径共同验证**：既构建独立 Flowglass，也显式选择完整 catalog 功能构建 Toolbox，再检查动态 payload/loader。构建器省略 `--features` 会默认只构建 Flowglass，不能拿默认构建成功代替完整 Toolbox 验证。

兼容测试至少覆盖：calc 输入/提交与结果、flowedit 编辑与图预览、一个含异步请求及详情的普通工具、组件启停、切换工作区/Session、卸载重挂。真实服务依赖可用脱敏 fixture/mock 验证，不为兼容检查执行有外部副作用的真实操作。

发布前分别检查 Toolbox 单独启用、Flowglass 单独启用、两者同时启用；覆盖主要支持的原生侧栏与降级路径。任何 Toolbox 功能回归都阻止对应共享改动发布，先修复或回退该阶段，不以 Flowglass 页面测试通过豁免。

## 13. 验收标准

### 13.1 用户任务验收

| 场景 | 完成条件 |
| --- | --- |
| 查看执行进度 | 首屏能辨认观察对象、运行状态和当前活动步骤 |
| 找到失败工具 | 错误保持可见，从卡片一次操作进入详情 |
| 查看节点内容 | 一次点击/键盘激活打开；关闭后回到原节点与阅读位置 |
| 查看子代理 | 显示层级与来源；一次返回回到上一级，不丢当前上下文 |
| 阅读历史 | 新数据不会强制拉到底；加载历史不明显跳动 |
| 比较分支 | 能找到同一轮各分支结论，区分未对齐与真实差异 |
| 继续并发任务 | 提交前看清目标数、新建/复用关系；失败结果逐项可见 |
| 编辑草稿 | 持续刷新、全屏切换后草稿和焦点不丢失 |
| 调整规则 | 默认先看到规则摘要；进入编辑后可保存/放弃，既有规则未丢失 |
| 仅键盘使用 | 完成查看、展开、切视图、打开/关闭详情和返回，不依赖拖拽 |
| 节点查找，组合 A/B | A 覆盖已加载内容，B 覆盖全会话；搜索范围明确，命中可定位，清除筛选恢复原视图 |
| 标记重要结论，组合 B | 能恢复到正确 Session/节点，失效标记有说明 |
| 带入分支结论，组合 C | 预览内容、来源与最终草稿一致，不自动发送 |
| 回放/导出，组合 D | 回放不执行任务；导出范围可预览，默认不附带隐藏原文 |

### 13.2 布局矩阵

- 面板宽度：360 / 480 / 720px，以及约 960px 宽面板。
- 全屏：1440×900 / 1920×1080；保留 1280×720 作为本轮观察基线。
- 主题：深色 / 浅色；默认字号 / 放大字号；普通动效 / 降低动效。
- 数据：0 / 1 / 60 / 超过 1000 条事件；1 / 2 / 4 分支；不同长度中文与英文输出。
- 普通时间流无横向溢出；图和显式并排比较具有清晰的移动与复位操作。

### 13.3 性能与稳定性目标

以下是待阶段 0 校准的建议门槛，测试应固定机器、fixture 与浏览器。记录 P95、采样次数和 Host/RPC 时间，不以一次人工感觉宣称达标。

| 指标 | 建议目标/方法 |
| --- | --- |
| 本地反馈 | 节点选中、打开菜单等反馈 P95 ≤100ms |
| 已加载数据的详情/视图切换 | P95 ≤300ms；需 RPC 的请求另列耗时 |
| 实时可见延迟 | 从接收 live revision 到对应 DOM 提交 P95 ≤500ms，不计模型首 token 时间 |
| 历史加载锚点 | 加载前后锚点偏移建议 ≤4px，且不改变用户选择 |
| 长会话 | 1000+ 事件样本首次可交互不明显回退；记录实际渲染节点数与 payload |
| 隐藏状态 | 无持续的 Flowglass 主动刷新；在途请求可收尾 |
| 生命周期 | 连续打开/关闭与切会话 20 次后，订阅/计时器/挂载点数量不持续增长 |
| 连续生成 | 草稿、焦点、选中与详情持续稳定；流式结算不生成重复卡片 |

### 13.4 必保回归边界

- 三条承载路径互斥，原生服务晚到/移除/注册失败有既定降级。
- 不同工作区、Session、静态 bundle 的状态和样式不会串用。
- 单会话 60 条分页、子代理返回、归档过滤与框选内容语义保持正确。
- 1→N、N→N、沿用当前、从回答节点分支与旧轮派生的目标保持正确。
- 失败、重试、取消、中断和流式结算身份连续。
- 历史拓扑不覆盖父轮；当前存储有最近 20 条记录上限，不能把“不覆盖拓扑”承诺成无限历史保存。
- 设置仍保存在当前浏览器；不写入 Session 日志或发布包。
- 原生 Flowglass 仍为静态 Host/Client/Remote，不增加动态 runner 或新的动态批准流程。

## 15. 迁移、回退与范围控制

每一阶段保持独立可回退。首版信息架构与视觉改动不改变 Session 数据格式；偏好新增 schema/version 时保留旧值可读与旧字段语义。不得通过删除用户历史或清空浏览器存储修复迁移问题。

短期可以保留旧视图别名和必要的渲染 fallback，但要标明用途与移除条件，避免长期维护两套完整产品界面。若原生结构化渲染尚未覆盖某个旧消费者，继续使用其现有 HTML 路径。

用户随后要求全部实施；本轮已加入第 10 节 A–D 的最小能力与相应源码、测试、文档，具体完成范围见实施记录。建议实施范围不包含以下工作：重建 Harness 的侧栏/标签体系、替换宿主 Markdown renderer、修改 agent loop 或 Session 持久化、引入大型图编辑器、增加云端同步/团队协作、无限历史存储、自动运行任务或自动发送消息。

当前方案可直接据此实施，无需先补充产品偏好。仍需在阶段 0 验证的技术问题是：实际 3080 构建与源码的一致性、宿主公开接口的支持范围、浅色主题的视觉基线、长会话瓶颈位置、旧规则动作的兼容调用面。
